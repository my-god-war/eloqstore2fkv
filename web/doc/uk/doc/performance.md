# Продуктивність

Завантажте `perf-latest` з `fkv_bench` зі сховища fkv і запустіть те саме навантаження на фіксованій машині.
Порівняйте пропускну спроможність, квантилі затримки та піковий RSS із базовим рівнем C++.

Джерело параметра узгоджується з fkv:

- `PERF_ROWS`
- `PERF_BATCH_SIZE`
- `PERF_WORKLOAD`
- `PERF_BENCH_ROOT`

Базовий рівень C++ виконується середовищем Oracle `simple_bench`, а потім виводиться відповідно до тієї самої схеми та публікується в
`perf-baseline` реліз ресурсу. Результати порівняння записуються назад у складський документ, і сайт безпосередньо рендерить Markdown.
Рівень даних JSON не підтримується.

## Поточні результати

базовий рівень схеми 2 для 2026-11-06T04:25Z,`github-ubuntu-latest-x86_64`, сторінка 4 КБ,
`data_append_mode=false`, `direct_io=true`. Фіксоване навантаження:
`rows/max_key=1000000`,`batch_size=100`,`write_batchs=10000`,
`read_per_part=4`,`partitions=1`,`kv_size=128`,`rng=cpp`
(`key_interval=4` / `del_ratio=4`), `test_secs=30`.

| Отримайте пропускну здатність | 5,526 QPS | 7,293 QPS | 1.32x |

Написання 1 мільйона записів (10 000 пакетів) відповідає
`io_write_at_num=48,625`, `io_data_sync_num=10,000`, тобто дані синхронізуються один раз на пакет.
Додаткові показники Rust: Scan `141,166 kv/s`, Fullscan `108,274 kv/s`, Write Amplification `2.57x`
(`proc_io_write` 329 МБ / 128 МБ логічних записів), `4.86` системні виклики запису на пакет.
Коефіцієнт зберігання обчислюється на основі номінальних даних 1 М × 128 Б = 128 МБ; Цього разу C++ не запускає GC/compact,
Тож він містить більше сторінок історії. Це не те саме число калібру, що "збільшення простору даних для виживання".
Затримка хвоста Rust P99.9 все ще гірша, ніж у C++ (поставте 223,3 мс проти 86,0 мс, отримаєте 355,5 мс проти
48,2 мс), єдина базова лінія сильно коливається, будь ласка, дивіться внутрішній звіт про продуктивність для деталей.

**Примітка**: C++ `write-read` означає, що потік запису та потік читання виконуються одночасно, а Rust зараз
«Завершіть написання, знову відкрийте та прочитайте знову», на етапі читання немає змагання з написання. Тому множник `write-read` не можна розглядати як
Чисте читання / чисте письмо висновок; суворе порівняння має бачити `scripts/perf_local.sh --symmetric`
Виводяться дві пари результатів: лише для запису та лише для читання. Окремі спільні числа бігунів використовуються лише для регресії
Тенденції, випуски оцінюються за допомогою медіани `--runs`.
