# Прадукцыйнасць

Спампуйце `perf-latest` з `fkv_bench` са сховішча fkv і запусціце тую ж нагрузку на стацыянарнай машыне.
І параўнайце прапускную здольнасць, квантылі затрымкі і пікавы RSS з базавым узроўнем C++.

Крыніца параметра адпавядае fkv:

- `PERF_ROWS`
- `PERF_BATCH_SIZE`
- `PERF_WORKLOAD`
- `PERF_BENCH_ROOT`

Базавая лінія C++ запускаецца асяроддзем Oracle `simple_bench`, а затым выводзіцца ў адпаведнасці з той жа схемай і публікуецца ў
`perf-baseline` вызваліць актыв. Вынікі параўнання запісваюцца назад у складскі дакумент, і сайт непасрэдна адлюстроўвае Markdown.
Узровень даных JSON не падтрымліваецца.

## Бягучыя вынікі

базавая лінія схемы 2 для 2026-11-06T04:25Z,`github-ubuntu-latest-x86_64`, старонка 4 КіБ,
`data_append_mode=false`, `direct_io=true`. Сталая нагрузка:
`rows/max_key=1000000`,`batch_size=100`,`write_batchs=10000`,
`read_per_part=4`,`partitions=1`,`kv_size=128`,`rng=cpp`
(`key_interval=4` / `del_ratio=4`), `test_secs=30`.

| праект | C++ EloqStore | Rust fkv | Rust / C++ |
|---|---:|---:|---:|
| Паставіць прапускную здольнасць | 16,866 kv/s | 21,377 kv/s | 1.27x |
| Атрымаць прапускную здольнасць | 5,526 QPS | 7,293 QPS | 1.32x |
| Пастаўце лагічную прапускную здольнасць | 2.06 MiB/s | 2.61 MiB/s | 1.27x |
| Атрымаць лагічную прапускную здольнасць | 0.67 MiB/s | 0.89 MiB/s | 1.32x |
| Put P99 | 51.2 ms | 35.1 ms | 0.69x |
| Get P99 | 31.2 ms | 10.0 ms | 0.32x |
| Put P99.9 | 86.0 ms | 223.3 ms | 2.60x |
| Get P99.9 | 48.2 ms | 355.5 ms | 7.37x |
| Пікавы RSS | 175.6 MiB | 145.5 MiB | 0.83x |
| Выкарыстанне памяці | 269.0 MiB | 101.4 MiB | 0.38x |
| Захоўванне / намінальныя дадзеныя | 2.20x | 0.83x | 0.38x |

Напісанне 1 мільёна запісаў (10 000 партый) адпавядае
`io_write_at_num=48,625`, `io_data_sync_num=10,000`, гэта значыць, дадзеныя сінхранізуюцца адзін раз на пакет.
Дадатковыя паказчыкі Rust: сканаванне `141,166 kv/s`, поўнае сканаванне `108,274 kv/s`, узмацненне запісу `2.57x`
(`proc_io_write` 329 МБ / 128 МБ лагічныя запісы), `4.86` сістэмныя выклікі запісу на пакет.
Каэфіцыент захоўвання разлічваецца на аснове 1M × 128B = 128 MB намінальных даных; C++ не запускае GC/compact на гэты раз,
Такім чынам, ён змяшчае больш старонак гісторыі. Гэта не той самы лік калібра, што "ўзмацненне прасторы дадзеных аб выжыванні".
Затрымка Rust P99.9 па-ранейшаму горшая, чым у C++ (пакладзеце 223,3 мс супраць 86,0 мс, атрымаеце 355,5 мс супраць
48,2 мс), адна базавая лінія моцна вагаецца, падрабязную інфармацыю глядзіце ва ўнутранай справаздачы аб прадукцыйнасці.

**Заўвага**: C++ `write-read` азначае, што паток запісу і паток чытання працуюць адначасова, і Rust зараз
"Завяршыце напісанне, адкрыйце і прачытайце яшчэ раз", на этапе чытання няма конкурсу пісьма. Таму множнік `write-read` не можа разглядацца як
Чыстае чытанне / чыста пісьмовае заключэнне; строгае параўнанне павінна бачыць `scripts/perf_local.sh --symmetric`
Выводзіцца дзве пары вынікаў: толькі для запісу і толькі для чытання. Адзіныя агульныя нумары бегуноў выкарыстоўваюцца толькі для рэгрэсіі
Тэндэнцыі, выпускі ацэньваюцца з дапамогай медыяны `--runs`.
