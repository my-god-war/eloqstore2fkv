# Производительность

Загрузите `perf-latest` из `fkv_bench` из репозитория fkv и запустите ту же рабочую нагрузку на стационарном компьютере.
И сравните пропускную способность, квантили задержки и пиковый RSS с базовым уровнем C++.

Источник параметра соответствует fkv:

- `PERF_ROWS`
- `PERF_BATCH_SIZE`
- `PERF_WORKLOAD`
- `PERF_BENCH_ROOT`

Базовая версия C++ запускается средой oracle `simple_bench`, а затем выводится в соответствии с той же схемой и публикуется в
`perf-baseline` освободить ресурс. Результаты сравнения записываются обратно в документ хранилища, и сайт напрямую отображает Markdown.
Уровень данных JSON не поддерживается.

## Текущие результаты

базовый план схемы 2 для 2026-11-06T04:25Z,`github-ubuntu-latest-x86_64`, страница 4 КиБ,
`data_append_mode=false`, `direct_io=true`. Фиксированная нагрузка:
`rows/max_key=1000000`,`batch_size=100`,`write_batchs=10000`,
`read_per_part=4`,`partitions=1`,`kv_size=128`,`rng=cpp`
(`key_interval=4` / `del_ratio=4`), `test_secs=30`.

Запись 1 миллиона записей (10 000 пакетов) соответствует
`io_write_at_num=48,625`, `io_data_sync_num=10,000`, то есть данные синхронизируются один раз для каждого пакета.
Дополнительные метрики Rust: сканирование `141,166 kv/s`, полное сканирование `108,274 kv/s`, усиление записи `2.57x`
(`proc_io_write` 329 МБ / 128 МБ логических записей), `4.86` запись системных вызовов за пакет.
Коэффициент хранения рассчитывается на основе номинальных данных 1M × 128B = 128 МБ; C++ на этот раз не запускает GC/compact,
Так что в нем больше страниц истории. Это не тот же номер калибра, что и «увеличение пространства данных выживания».
Задержка хвоста Rust P99.9 по-прежнему хуже, чем у C++ (положим 223,3 мс против 86,0 мс, получим 355,5 мс против
48,2 мс), единая базовая линия сильно колеблется, подробности см. во внутреннем отчете о производительности.

**Примечание**: `write-read` в C++ означает, что поток записи и поток чтения выполняются одновременно, и в настоящее время в Rust
«Завершите написание, снова откройте и прочитайте еще раз», на этапе чтения конкурс сочинений не проводится. Поэтому множитель `write-read` нельзя рассматривать как
Чистое чтение/чистое письменное заключение; строгое сравнение должно видеть `scripts/perf_local.sh --symmetric`
Выводятся две пары результатов: только для записи и только для чтения. Одиночные общие номера бегунов используются только для регрессии.
Тенденции и выпуски оцениваются по медиане `--runs`.
