# 06-11-2026: ตารางประสิทธิภาพของโฮมเพจ การขยายตัวบ่งชี้ และเพจ

การอัปเดตวันนี้มุ่งเน้นไปที่การตรวจสอบประสิทธิภาพและการเปิดตัวไซต์

## การเปรียบเทียบประสิทธิภาพของโฮมเพจ

- หน้าแรกถูกเปลี่ยนเป็นลำดับความสำคัญของประสิทธิภาพ และตารางเปรียบเทียบ C++/Rust จะแสดงโดยตรงบนหน้าจอแรก
- มีการเพิ่มตัวบ่งชี้ใหม่สามชุด: แบนด์วิดท์แบบลอจิคัล, ความล่าช้าหาง P99.9 และการขยายเชิงพื้นที่
- เพิ่มรายละเอียดการทำงานของ Rust: การสแกน, Fullscan, การขยายการเขียน, จำนวนการเรียกระบบการเขียน และการซิงโครไนซ์ข้อมูลต่อชุด
- ทำเครื่องหมาย `write-read` อย่างชัดเจนว่าเป็นความสามารถผสมและลิงก์ไปยังเอกสารประกอบการปฏิบัติงาน

พื้นฐานเครื่องเดียวกันปัจจุบัน:

| ดัชนี | C++ | Rust | Rust / C++ |
|---|---:|---:|---:|
| Put | 16,866 kv/s | 21,377 kv/s | 1.27x |
| Get | 5,526 QPS | 7,293 QPS | 1.32x |
| Put P99 | 51.2 ms | 35.1 ms | 0.69x |
| Get P99 | 31.2 ms | 10.0 ms | 0.32x |
| Put P99.9 | 86.0 ms | 223.3 ms | 2.60x |
| Get P99.9 | 48.2 ms | 355.5 ms | 7.37x |
| RSS สูงสุด | 175.6 MiB | 145.5 MiB | 0.83x |
| การใช้พื้นที่เก็บข้อมูล | 269.0 MiB | 101.4 MiB | 0.38x |

## ตัวชี้วัดการประเมินผล

อ้างถึงผลลัพธ์ทั่วไปของ RocksDB, LevelDB, YCSB, WiredTiger และการวัดประสิทธิภาพอื่น ๆ ฉันเพิ่ม:

- แบนด์วิธการอ่านและเขียนแบบลอจิคัล MiB/s;
- ความล่าช้าหาง P99.9;
- การขยายพื้นที่ การขยายการเขียน
- จำนวนการเรียกระบบการเขียนและการซิงโครไนซ์ข้อมูลในแต่ละแบตช์
- สแกน / สแกนแบบเต็ม;
- CPU, ข้อบกพร่องของเพจ, การสลับบริบท และกระบวนการ IO ยังคงถูกรวบรวมโดยตัวช่วยทรัพยากร

เกษียณอายุพร้อมๆ กัน`gxhash_4096B_gib_s`. เป็นไมโครเบนช์มาร์กแฮชบล็อกเดี่ยวขนาด 4 KiB ที่ไม่ได้อยู่บนเส้นทางเอ็นจิ้น KV และไม่มีเวอร์ชันที่เทียบเท่ากับ C++

## ความถูกต้องและการแก้ไขทางวิศวกรรม

- แก้ไขพื้นที่คีย์ของ `--rng cpp` read/scan: การตรวจจับการอ่านจะไม่คูณด้วย `key_interval` อีกต่อไป เพื่อหลีกเลี่ยงไม่ให้การอ่าน 75% ไปอยู่ในคีย์ที่ไม่ได้เขียนไว้
- แก้ไขการพยายามสแตนด์บายใหม่ที่เกิดจาก macOS `openrsync` ตัดสินรายการที่มีเนื้อหาเดียวกันไม่ถูกต้อง
- แก้ไขปัญหาเกตฮาร์ดแวร์ที่ดิสก์เสมือน QEMU ถูกตัดสินผิดว่าเป็น SSD ในเครื่อง

## ไซต์และการเผยแพร่

- เปิดใช้งานเพจ GitHub: <https://my-god-war.github.io/eloqstore2fkv/>
- การกำหนดเส้นทางไซต์รองรับเส้นทางย่อย `/eloqstore2fkv/`
- เอกสารถูกอ่านจาก `raw.githubusercontent.com` แทน และ 404 ที่เกิดจากการหายไป `web/` ในเส้นทาง jsDelivr ได้รับการแก้ไขแล้ว
- การนำทางในบล็อกและการแปลหลายภาษาของ `bun run tran` ได้รับการบูรณาการเข้าด้วยกัน บทความนี้ได้รับการแปลโดยอัตโนมัติจากต้นฉบับภาษาจีนเป็นภาษาอื่น
