# کارکردگی

fkv ریپوزٹری سے `perf-latest` کا `fkv_bench` ڈاؤن لوڈ کریں اور اسی کام کا بوجھ ایک مقررہ مشین پر چلائیں۔
اور تھرو پٹ، لیٹنسی کوانٹائلز، اور چوٹی RSS کا C++ بیس لائن سے موازنہ کریں۔

پیرامیٹر کا ذریعہ fkv کے مطابق ہے:

- `PERF_ROWS`
- `PERF_BATCH_SIZE`
- `PERF_WORKLOAD`
- `PERF_BENCH_ROOT`

C++ بیس لائن کو اوریکل ماحول `simple_bench` کے ذریعہ چلایا جاتا ہے اور پھر اسی اسکیما کے مطابق آؤٹ پٹ اور شائع کیا جاتا ہے۔
`perf-baseline` ریلیز اثاثہ۔ موازنہ کے نتائج واپس گودام دستاویز میں لکھے جاتے ہیں، اور سائٹ براہ راست مارک ڈاؤن کو پیش کرتی ہے۔
کوئی JSON ڈیٹا پرت برقرار نہیں ہے۔

## موجودہ نتائج

اسکیما 2 بیس لائن برائے 2026-11-06T04:25Z,`github-ubuntu-latest-x86_64`، 4 KiB صفحہ،
`data_append_mode=false`، `direct_io=true`۔ مقررہ کام کا بوجھ:
`rows/max_key=1000000`،`batch_size=100`،`write_batchs=10000`،
`read_per_part=4`،`partitions=1`،`kv_size=128`،`rng=cpp`
(`key_interval=4` / `del_ratio=4`، `test_secs=30`۔

1 ملین اندراجات لکھنا (10,000 بیچز) کے مساوی ہے۔
`io_write_at_num=48,625`، `io_data_sync_num=10,000`، یعنی ڈیٹا ایک بار فی بیچ میں مطابقت پذیر ہوتا ہے۔
زنگ آلود اضافی میٹرکس: اسکین `141,166 kv/s`، فل اسکین `108,274 kv/s`، ایمپلیفیکیشن لکھیں `2.57x`
(`proc_io_write` 329 MB / 128 MB منطقی تحریریں)، `4.86` فی بیچ سسٹم کالز لکھیں۔
اسٹوریج کا تناسب 1M × 128B = 128 MB برائے نام ڈیٹا کی بنیاد پر لگایا جاتا ہے۔ C++ اس بار GC/compact کو متحرک نہیں کرتا ہے،
چنانچہ اس میں تاریخ کے مزید صفحات ہیں۔ یہ "بقا ڈیٹا اسپیس ایمپلیفیکیشن" جیسا کیلیبر نمبر نہیں ہے۔
زنگ کی P99.9 ٹیل لیٹینسی اب بھی C++ سے بدتر ہے (223.3 ms بمقابلہ 86.0 ms، حاصل کریں 355.5 ms بمقابلہ
48.2 ms)، سنگل بیس لائن میں بہت زیادہ اتار چڑھاؤ آتا ہے، براہ کرم تفصیلات کے لیے اندرونی پرف رپورٹ دیکھیں۔

**نوٹ**: C++ کا `write-read` مطلب ہے کہ تحریری دھاگہ اور پڑھنے کا دھاگہ ایک ہی وقت میں چلتے ہیں، اور اس وقت زنگ لگ رہا ہے۔
"مکمل تحریر، دوبارہ کھولیں، اور دوبارہ پڑھیں"، پڑھنے کے مرحلے میں تحریری مقابلہ نہیں ہے۔ اس لیے `write-read` کے ضرب کو نہیں سمجھا جا سکتا
خالص پڑھنا / خالص تحریری نتیجہ؛ سخت موازنہ `scripts/perf_local.sh --symmetric` دیکھنا چاہیے۔
نتائج کے دو جوڑے آؤٹ پٹ ہیں: صرف لکھنے کے لیے اور صرف پڑھنے کے لیے۔ واحد مشترکہ رنر نمبر صرف رجعت کے لیے استعمال کیے جاتے ہیں۔
رجحانات، ریلیز کا اندازہ `--runs` کا میڈین استعمال کرتے ہوئے کیا جاتا ہے۔
