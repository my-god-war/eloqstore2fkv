# કામગીરી

fkv રિપોઝીટરીમાંથી `perf-latest` માંથી `fkv_bench` ડાઉનલોડ કરો અને એ જ વર્કલોડને નિશ્ચિત મશીન પર ચલાવો.
અને થ્રુપુટ, લેટન્સી ક્વોન્ટાઇલ્સ અને પીક RSS ને C++ બેઝલાઇન સાથે સરખાવો.

પરિમાણ સ્ત્રોત fkv સાથે સુસંગત છે:

- `PERF_ROWS`
- `PERF_BATCH_SIZE`
- `PERF_WORKLOAD`
- `PERF_BENCH_ROOT`

C++ બેઝલાઇન ઓરેકલ એન્વાયર્નમેન્ટ `simple_bench` દ્વારા ચલાવવામાં આવે છે અને પછી તે જ સ્કીમા અનુસાર આઉટપુટ અને પ્રકાશિત થાય છે
`perf-baseline` રીલીઝ એસેટ. સરખામણી પરિણામો વેરહાઉસ દસ્તાવેજ પર પાછા લખવામાં આવે છે, અને સાઇટ સીધી માર્કડાઉન રેન્ડર કરે છે.
કોઈ JSON ડેટા સ્તર જાળવવામાં આવતું નથી.

(`proc_io_write` 329 MB / 128 MB લોજિકલ લખે છે), `4.86` બેચ દીઠ સિસ્ટમ કૉલ્સ લખો.
સ્ટોરેજ રેશિયો 1M × 128B = 128 MB નોમિનલ ડેટાના આધારે ગણવામાં આવે છે; C++ આ વખતે GC/કોમ્પેક્ટને ટ્રિગર કરતું નથી,
તેથી તેમાં ઈતિહાસના વધુ પાના છે. તે "સર્વાઇવલ ડેટા સ્પેસ એમ્પ્લીફિકેશન" જેવો જ કેલિબર નંબર નથી.
રસ્ટની P99.9 પૂંછડી લેટન્સી હજુ પણ C++ કરતાં વધુ ખરાબ છે (223.3 ms vs 86.0 ms મૂકો, 355.5 ms vs મેળવો
48.2 ms), સિંગલ બેઝલાઇનમાં મોટા પ્રમાણમાં વધઘટ થાય છે, વિગતો માટે કૃપા કરીને આંતરિક પર્ફ રિપોર્ટ જુઓ.

**નોંધ**: C++ નો `write-read` અર્થ એ છે કે લેખન થ્રેડ અને વાંચન થ્રેડ એક જ સમયે ચાલે છે અને હાલમાં કાટ લાગે છે
"સંપૂર્ણ લેખન, ફરીથી ખોલો અને ફરીથી વાંચો", વાંચન તબક્કામાં કોઈ લેખન સ્પર્ધા નથી. તેથી `write-read` ના ગુણકને ગણી શકાય નહીં
શુદ્ધ વાંચન / શુદ્ધ લેખન નિષ્કર્ષ; કડક સરખામણી `scripts/perf_local.sh --symmetric` જોવી જોઈએ
પરિણામોની બે જોડી આઉટપુટ છે: ફક્ત લખવા માટે અને ફક્ત વાંચવા માટે. સિંગલ શેર્ડ રનર નંબરનો ઉપયોગ માત્ર રીગ્રેસન માટે થાય છે
`--runs` ના મધ્યકનો ઉપયોગ કરીને વલણો, રિલીઝનું મૂલ્યાંકન કરવામાં આવે છે.
