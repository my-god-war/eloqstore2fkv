# စွမ်းဆောင်ရည်

fkv repository မှ `perf-latest` ၏ `perf-latest`ကို ဒေါင်းလုဒ်လုပ်ကာ ပုံသေစက်ပေါ်တွင် တူညီသောအလုပ်ပမာဏကို လုပ်ဆောင်ပါ။
ပြီးလျှင် ဖြတ်သန်းမှု၊ တုံ့ပြန်မှုပမာဏနှင့် အမြင့်ဆုံး RSS ကို C++ အခြေခံလိုင်းတစ်ခုနှင့် နှိုင်းယှဉ်ပါ။

ကန့်သတ်အရင်းအမြစ်သည် fkv နှင့် ကိုက်ညီသည်-

- `PERF_ROWS`
- `PERF_BATCH_SIZE`
- `PERF_WORKLOAD`
- `PERF_BENCH_ROOT`

C++ အခြေခံလိုင်းကို oracle ပတ်၀န်းကျင် `simple_bench`ဖြင့် လုပ်ဆောင်ပြီး တူညီသော schema အရ ထုတ်ပေးပြီး ထုတ်ဝေရန်၊
`perf-baseline` ပိုင်ဆိုင်မှုကို ထုတ်လွှတ်ပါ။ နှိုင်းယှဉ်မှုရလဒ်များကို သိုလှောင်ရုံစာရွက်စာတမ်းသို့ ပြန်လည်ရေးသားထားပြီး ဆိုက်သည် Markdown ကို တိုက်ရိုက်ပြန်ဆိုသည်။
JSON ဒေတာအလွှာကို ထိန်းသိမ်းထားခြင်းမရှိပါ။

`io_write_at_num=48,625`၊ `io_data_sync_num=10,000` ဆိုလိုသည်မှာ၊ ဒေတာကို တစ်သုတ်လျှင် တစ်ကြိမ် ထပ်တူပြုပါသည်။
သံချေးတက်နေသော အပိုမက်ထရစ်များ- စကင်န် `141,166 kv/s`၊ Fullscan `108,274 kv/s`၊ ချဲ့ထွင်မှု `2.57x`ရေးပါ
(`proc_io_write` 329 MB / 128 MB ယုတ္တိနည်းဖြင့် ရေးသားသည်)၊ `4.86` တစ်သုတ်လျှင် စနစ်ခေါ်ဆိုမှုများကို ရေးပါ။
သိုလှောင်မှုအချိုးကို 1M × 128B = 128 MB အမည်ခံဒေတာအပေါ် အခြေခံ၍ တွက်ချက်ပါသည်။ C++ သည် ယခုတစ်ကြိမ်တွင် GC/compact ကို အစပျိုးခြင်းမရှိပါ။
ထို့ကြောင့် ၎င်းတွင် သမိုင်းစာမျက်နှာများ ပိုများသည်။ ၎င်းသည် "survival data space amplification" ကဲ့သို့ caliber number မဟုတ်ပါ။
Rust ၏ P99.9 tail latency သည် C++ ထက် ပိုဆိုးနေသေးသည် (223.3 ms နှင့် 86.0 ms ကိုထည့်ပါ၊ 355.5 ms နှင့် ရယူပါ
48.2 ms) တစ်ခုတည်းသော အခြေခံအချက်သည် အလွန်အတက်အကျဖြစ်နေသည်၊ အသေးစိတ်အတွက် internal perf အစီရင်ခံစာကို ကြည့်ပါ။

**မှတ်ချက်**: C++ ၏ `write-read` ဆိုလိုသည်မှာ စာရေးစာတန်းနှင့် စာဖတ်သည့်တွဲသည် တစ်ချိန်တည်းတွင် အလုပ်လုပ်နေပြီး လက်ရှိတွင် Rust၊
"စာရေးပါ၊ ပြန်ဖွင့်ပါ၊ ထပ်ဖတ်ပါ" ဟူ၍ စာဖတ်ခြင်းအဆင့်တွင် စာရေးပြိုင်ပွဲမရှိပါ။ ထို့ကြောင့် `write-read` ၏ မြှောက်ကိန်းကို အဖြစ် သတ်မှတ်၍ မရပါ။
စင်ကြယ်သောစာဖတ်ခြင်း / စင်ကြယ်သောအရေးအသားနိဂုံးချုပ်; တင်းကျပ်သော နှိုင်းယှဉ်ချက်ကို `scripts/perf_local.sh --symmetric` မြင်ရပါမည်။
ရလဒ်အတွဲနှစ်ခုသည် အထွက်- ရေး-သပ်သပ်နှင့် ဖတ်ရန်သာဖြစ်သည်။ တစ်ခုတည်းသော မျှဝေထားသော အပြေးသမားနံပါတ်များကို ဆုတ်ယုတ်ခြင်းအတွက်သာ အသုံးပြုပါသည်။
ခေတ်ရေစီးကြောင်းများ၊ ထုတ်ဝေမှုများကို `--runs` ၏ အလယ်ဗဟိုကို အသုံးပြု၍ အကဲဖြတ်ပါသည်။
