# 2026-11-06: საწყისი გვერდის მუშაობის ცხრილი, ინდიკატორის გაფართოება და გვერდები

დღევანდელი განახლება ფოკუსირებულია შესრულების მიმოხილვებზე და საიტის გაშვებაზე.

## საწყისი გვერდის შესრულების შედარება

- საწყისი გვერდი შეიცვალა შესრულების პრიორიტეტად და C++/Rust შედარების ცხრილი პირდაპირ ნაჩვენებია პირველ ეკრანზე.
- დამატებულია ინდიკატორების სამი ახალი ნაკრები: ლოგიკური გამტარობა, P99.9 კუდის დაყოვნება და სივრცითი გაძლიერება.
- დამატებულია Rust გაშვებული დეტალები: სკანირება, სრული სკანირება, ჩაწერის გაძლიერება, ჩაწერის სისტემური ზარების რაოდენობა და მონაცემთა სინქრონიზაცია თითო პარტიაში.
- მკაფიოდ მონიშნეთ `write-read` შერეულ კალიბრად და ბმული შესრულების დოკუმენტაციასთან.

ამჟამინდელი იგივე მანქანის საბაზისო ხაზი:

| ინდექსი | C++ | Rust | Rust / C++ |
|---|---:|---:|---:|
| Put | 16,866 kv/s | 21,377 kv/s | 1.27x |
| Get | 5,526 QPS | 7,293 QPS | 1.32x |
| Put P99 | 51.2 ms | 35.1 ms | 0.69x |
| Get P99 | 31.2 ms | 10.0 ms | 0.32x |
| Put P99.9 | 86.0 ms | 223.3 ms | 2.60x |
| Get P99.9 | 48.2 ms | 355.5 ms | 7.37x |
| პიკი RSS | 175.6 MiB | 145.5 MiB | 0.83x |
| შენახვის გამოყენება | 269.0 MiB | 101.4 MiB | 0.38x |

## შეფასების ინდიკატორები

RocksDB, LevelDB, YCSB, WiredTiger და სხვა ეტალონების საერთო გამომავალზე მითითებით, მე დავამატე:

- წაკითხვის და ჩაწერის ლოგიკური გამტარუნარიანობა MiB/s;
- P99.9 კუდის დაყოვნება;
- სივრცის გაძლიერება, წერის გაძლიერება;
- ჩაწერის სისტემური ზარების რაოდენობა და მონაცემთა სინქრონიზაცია თითოეულ პარტიაში;
- სკანირების / სრული სკანირების გამტარუნარიანობა;
- CPU, გვერდის ხარვეზები, კონტექსტური გადამრთველები და პროცესის IO გრძელდება რესურსის გვერდითი კარის მიერ შეგროვებული.

ამავე დროს პენსიაზე გავიდა`gxhash_4096B_gib_s`. ეს არის 4 KiB ერთი ბლოკის ჰეშის მიკრობენჩმარკი, რომელიც არ არის KV ძრავის გზაზე და არ აქვს C++ ანალოგი.

## სისწორე და საინჟინრო შესწორებები

- დააფიქსირეთ `--rng cpp` წაკითხვის/სკანირების გასაღების სივრცე: წაკითხვის ამოცნობა აღარ მრავლდება `key_interval`-ზე, რათა თავიდან აიცილოთ წაკითხვის 75% დაუწერელ გასაღებებში ჩავარდნას.
- დაფიქსირდა ლოდინის რეჟიმში განმეორებითი ცდები, რომლებიც გამოწვეული იყო macOS `openrsync` მანიფესტების არასწორად შეფასებით იმავე შინაარსით.
- დაფიქსირდა ტექნიკის კარიბჭის პრობლემა, სადაც QEMU ვირტუალური დისკები არასწორად იყო შეფასებული, როგორც ადგილობრივი SSD.
