# ಕಾರ್ಯಕ್ಷಮತೆ

fkv ರೆಪೊಸಿಟರಿಯಿಂದ `perf-latest` ಆಫ್ `fkv_bench` ಅನ್ನು ಡೌನ್‌ಲೋಡ್ ಮಾಡಿ ಮತ್ತು ಸ್ಥಿರ ಗಣಕದಲ್ಲಿ ಅದೇ ಕೆಲಸದ ಹೊರೆಯನ್ನು ರನ್ ಮಾಡಿ.
ಮತ್ತು ಥ್ರೋಪುಟ್, ಲೇಟೆನ್ಸಿ ಕ್ವಾಂಟೈಲ್‌ಗಳು ಮತ್ತು ಗರಿಷ್ಠ RSS ಅನ್ನು C++ ಬೇಸ್‌ಲೈನ್‌ಗೆ ಹೋಲಿಸಿ.

ಪ್ಯಾರಾಮೀಟರ್ ಮೂಲವು fkv ಯೊಂದಿಗೆ ಸ್ಥಿರವಾಗಿದೆ:

- `PERF_ROWS`
- `PERF_BATCH_SIZE`
- `PERF_WORKLOAD`
- `PERF_BENCH_ROOT`

C++ ಬೇಸ್‌ಲೈನ್ ಅನ್ನು ಒರಾಕಲ್ ಪರಿಸರದಿಂದ ಚಾಲನೆ ಮಾಡಲಾಗುತ್ತದೆ `simple_bench` ಮತ್ತು ನಂತರ ಅದೇ ಸ್ಕೀಮಾ ಪ್ರಕಾರ ಔಟ್‌ಪುಟ್ ಮಾಡಿ ಮತ್ತು ಪ್ರಕಟಿಸಲಾಗಿದೆ
`perf-baseline` ಸ್ವತ್ತು ಬಿಡುಗಡೆ. ಹೋಲಿಕೆ ಫಲಿತಾಂಶಗಳನ್ನು ಗೋದಾಮಿನ ಡಾಕ್ಯುಮೆಂಟ್‌ಗೆ ಮತ್ತೆ ಬರೆಯಲಾಗುತ್ತದೆ ಮತ್ತು ಸೈಟ್ ನೇರವಾಗಿ ಮಾರ್ಕ್‌ಡೌನ್ ಅನ್ನು ನೀಡುತ್ತದೆ.
ಯಾವುದೇ JSON ಡೇಟಾ ಲೇಯರ್ ಅನ್ನು ನಿರ್ವಹಿಸಲಾಗಿಲ್ಲ.

ತುಕ್ಕು ಹೆಚ್ಚುವರಿ ಮೆಟ್ರಿಕ್‌ಗಳು: ಸ್ಕ್ಯಾನ್ `141,166 kv/s`, ಪೂರ್ಣ ಸ್ಕ್ಯಾನ್ `108,274 kv/s`, ಆಂಪ್ಲಿಫಿಕೇಶನ್ ಬರೆಯಿರಿ `2.57x`
(`proc_io_write` 329 MB / 128 MB ತಾರ್ಕಿಕ ಬರಹಗಳು), `4.86` ಪ್ರತಿ ಬ್ಯಾಚ್‌ಗೆ ಸಿಸ್ಟಮ್ ಕರೆಗಳನ್ನು ಬರೆಯಿರಿ.
ಶೇಖರಣಾ ಅನುಪಾತವನ್ನು 1M × 128B = 128 MB ನಾಮಮಾತ್ರ ಡೇಟಾದ ಆಧಾರದ ಮೇಲೆ ಲೆಕ್ಕಹಾಕಲಾಗುತ್ತದೆ; C++ ಈ ಸಮಯದಲ್ಲಿ GC/ಕಾಂಪ್ಯಾಕ್ಟ್ ಅನ್ನು ಪ್ರಚೋದಿಸುವುದಿಲ್ಲ,
ಆದ್ದರಿಂದ ಇದು ಇತಿಹಾಸದ ಹೆಚ್ಚಿನ ಪುಟಗಳನ್ನು ಒಳಗೊಂಡಿದೆ. ಇದು "ಸರ್ವೈವಲ್ ಡೇಟಾ ಸ್ಪೇಸ್ ವರ್ಧನೆ" ಯಂತೆಯೇ ಅದೇ ಕ್ಯಾಲಿಬರ್ ಸಂಖ್ಯೆ ಅಲ್ಲ.
ರಸ್ಟ್‌ನ P99.9 ಟೈಲ್ ಲೇಟೆನ್ಸಿ ಇನ್ನೂ C++ ಗಿಂತ ಕೆಟ್ಟದಾಗಿದೆ (223.3 ms vs 86.0 ms ಹಾಕಿ, 355.5 ms ವಿರುದ್ಧ ಪಡೆಯಿರಿ
48.2 ms), ಸಿಂಗಲ್ ಬೇಸ್‌ಲೈನ್ ಹೆಚ್ಚು ಏರಿಳಿತಗೊಳ್ಳುತ್ತದೆ, ದಯವಿಟ್ಟು ವಿವರಗಳಿಗಾಗಿ ಆಂತರಿಕ ಪರ್ಫ್ ವರದಿಯನ್ನು ನೋಡಿ.

**ಗಮನಿಸಿ**: C++ ನ `write-read` ಎಂದರೆ ಬರವಣಿಗೆ ಥ್ರೆಡ್ ಮತ್ತು ಓದುವ ಥ್ರೆಡ್ ಒಂದೇ ಸಮಯದಲ್ಲಿ ಚಲಿಸುತ್ತದೆ ಮತ್ತು ಪ್ರಸ್ತುತ ರಸ್ಟ್
"ಬರೆಯುವಿಕೆಯನ್ನು ಪೂರ್ಣಗೊಳಿಸಿ, ಪುನಃ ತೆರೆಯಿರಿ ಮತ್ತು ಮತ್ತೆ ಓದಿ", ಓದುವ ಹಂತದಲ್ಲಿ ಯಾವುದೇ ಬರವಣಿಗೆ ಸ್ಪರ್ಧೆಯಿಲ್ಲ. ಆದ್ದರಿಂದ `write-read` ಗುಣಕವನ್ನು ಹೀಗೆ ಪರಿಗಣಿಸಲಾಗುವುದಿಲ್ಲ
ಶುದ್ಧ ಓದುವಿಕೆ / ಶುದ್ಧ ಬರವಣಿಗೆಯ ತೀರ್ಮಾನ; ಕಟ್ಟುನಿಟ್ಟಾದ ಹೋಲಿಕೆಯು `scripts/perf_local.sh --symmetric` ಅನ್ನು ನೋಡಬೇಕು
ಎರಡು ಜೋಡಿ ಫಲಿತಾಂಶಗಳು ಔಟ್‌ಪುಟ್ ಆಗಿವೆ: ಬರವಣಿಗೆ-ಮಾತ್ರ ಮತ್ತು ಓದಲು-ಮಾತ್ರ. ಏಕ ಹಂಚಿದ ರನ್ನರ್ ಸಂಖ್ಯೆಗಳನ್ನು ಹಿಂಜರಿತಕ್ಕಾಗಿ ಮಾತ್ರ ಬಳಸಲಾಗುತ್ತದೆ
ಟ್ರೆಂಡ್‌ಗಳು, ಬಿಡುಗಡೆಗಳನ್ನು `--runs` ನ ಸರಾಸರಿಯನ್ನು ಬಳಸಿಕೊಂಡು ನಿರ್ಣಯಿಸಲಾಗುತ್ತದೆ.
