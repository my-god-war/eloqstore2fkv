# செயல்திறன்

fkv களஞ்சியத்திலிருந்து `perf-latest` இன் `fkv_bench`ஐப் பதிவிறக்கி, அதே பணிச்சுமையை ஒரு நிலையான கணினியில் இயக்கவும்.
செயல்திறன், தாமத அளவுகள் மற்றும் உச்ச RSS ஆகியவற்றை C++ அடிப்படையுடன் ஒப்பிடுக.

அளவுரு மூலமானது fkv உடன் ஒத்துப்போகிறது:

- `PERF_ROWS`
- `PERF_BATCH_SIZE`
- `PERF_WORKLOAD`
- `PERF_BENCH_ROOT`

C++ அடிப்படையானது ஆரக்கிள் சூழலால் இயக்கப்படுகிறது `simple_bench` பின்னர் அதே திட்டத்தின் படி வெளியீடு மற்றும் வெளியிடப்பட்டது
`perf-baseline` சொத்தை விடுவிக்கவும். ஒப்பீட்டு முடிவுகள் கிடங்கு ஆவணத்திற்கு மீண்டும் எழுதப்படுகின்றன, மேலும் தளம் நேரடியாக மார்க் டவுனை வழங்குகிறது.
JSON தரவு அடுக்கு பராமரிக்கப்படவில்லை.

ரஸ்ட் கூடுதல் அளவீடுகள்: ஸ்கேன் `141,166 kv/s`, முழு ஸ்கேன் `108,274 kv/s`, பெருக்கத்தை எழுது `2.57x`

சேமிப்பக விகிதம் 1M × 128B = 128 MB பெயரளவு தரவுகளின் அடிப்படையில் கணக்கிடப்படுகிறது; C++ ஆனது இந்த நேரத்தில் GC/compact ஐ தூண்டாது,
எனவே இது வரலாற்றின் அதிக பக்கங்களைக் கொண்டுள்ளது. இது "சர்வைவல் டேட்டா ஸ்பேஸ் பெருக்கம்" போன்ற அதே காலிபர் எண் அல்ல.
ரஸ்டின் P99.9 டெயில் லேட்டன்சி C++ ஐ விட மோசமாக உள்ளது (223.3 ms vs 86.0 ms, 355.5 ms vs கிடைக்கும்
48.2 எம்.எஸ்), ஒற்றை அடிப்படையானது பெரிதும் ஏற்ற இறக்கமாக உள்ளது, விவரங்களுக்கு உள் பெர்ஃப் அறிக்கையைப் பார்க்கவும்.

**குறிப்பு**: C++ இன் `write-read` என்பது எழுதும் இழையும் படிக்கும் இழையும் ஒரே நேரத்தில் இயங்குகிறது, தற்போது Rust
"எழுத்து முடிக்கவும், மீண்டும் திறக்கவும், மீண்டும் படிக்கவும்", வாசிப்பு நிலையில் எழுத்துப் போட்டி இல்லை. எனவே `write-read`ன் பெருக்கியை இவ்வாறு கருத முடியாது
தூய வாசிப்பு / தூய எழுத்து முடிவு; கண்டிப்பான ஒப்பீடு `scripts/perf_local.sh --symmetric`ஐப் பார்க்க வேண்டும்
இரண்டு ஜோடி முடிவுகள் வெளியீடு: எழுத மட்டும் மற்றும் படிக்க மட்டும். ஒற்றைப் பகிரப்பட்ட ரன்னர் எண்கள் பின்னடைவுக்கு மட்டுமே பயன்படுத்தப்படுகின்றன
போக்குகள், வெளியீடுகள் `--runs`ன் சராசரியைப் பயன்படுத்தி மதிப்பிடப்படுகின்றன.
