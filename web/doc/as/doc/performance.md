# কাৰ্যক্ষমতা

fkv ভঁৰালৰ পৰা `perf-latest` ৰ `perf-latest` ডাউনলোড কৰক আৰু একেটা কাৰ্য্যভাৰ এটা স্থিৰ যন্ত্ৰত চলাওক ।
আৰু থ্ৰুপুট, লেটেন্সি কোৱাণ্টাইল, আৰু শীৰ্ষ RSSক এটা C++ ভিত্তিৰেখাৰ সৈতে তুলনা কৰক।

প্ৰাচল উৎস fkv ৰ সৈতে সামঞ্জস্যপূৰ্ণ:

- `PERF_ROWS`
- `PERF_BATCH_SIZE`
- `PERF_WORKLOAD`
- `PERF_BENCH_ROOT`

C++ ভিত্তিৰেখা oracle পৰিৱেশ `simple_bench` দ্বাৰা পৰিচালিত হয় আৰু তাৰ পিছত একে আঁচনি অনুসৰি আউটপুট আৰু প্ৰকাশ কৰা হয়
`perf-baseline` সম্পত্তি মুকলি কৰক। তুলনাৰ ফলাফলসমূহ গুদাম নথিপত্ৰলৈ পুনৰ লিখা হয়, আৰু চাইটে প্ৰত্যক্ষভাৱে মাৰ্কডাউন ৰেণ্ডাৰ কৰে।
কোনো JSON তথ্য স্তৰ ৰক্ষণাবেক্ষণ কৰা হোৱা নাই।

গতিকে ইয়াত ইতিহাসৰ আৰু পৃষ্ঠা সন্নিবিষ্ট কৰা হৈছে। ই "ছাৰভাইভেল ডাটা স্পেচ এম্প্লিফিকেশন"ৰ সৈতে একে কেলিবাৰ নম্বৰ নহয়।
Rust ৰ P99.9 টেইল লেটেন্সি এতিয়াও C++ তকৈ বেয়া (223.3 ms বনাম 86.0 ms ৰাখক, 355.5 ms বনাম পাওক
48.2 ms), একক ভিত্তিৰেখা বহু পৰিমাণে উঠা-নমা কৰে, বিৱৰণৰ বাবে অনুগ্ৰহ কৰি আভ্যন্তৰীণ perf প্ৰতিবেদন চাওক।

**টোকা**: C++ ৰ `write-read` ৰ অৰ্থ হ'ল লিখাৰ থ্ৰেড আৰু পঢ়া থ্ৰেড একে সময়তে চলে, আৰু Rust বৰ্তমানে
"লিখা সম্পূৰ্ণ কৰক, পুনৰ খুলি লওক, আৰু পুনৰ পঢ়ক", পঢ়াৰ পৰ্যায়ত লিখাৰ প্ৰতিযোগিতা নাই। গতিকে `write-read` ৰ গুণকক হিচাপে গণ্য কৰিব নোৱাৰি
বিশুদ্ধ পঠন / বিশুদ্ধ লেখাৰ সিদ্ধান্ত; কঠোৰ তুলনাই `scripts/perf_local.sh --symmetric` চাব লাগে
দুটা যোৰ ফলাফল আউটপুট হয়: কেৱল লিখা আৰু কেৱল পঢ়া। একক অংশীদাৰী দৌৰবিদ সংখ্যা কেৱল ৰিগ্ৰেছনৰ বাবে ব্যৱহাৰ কৰা হয়
