# Արտադրողականություն

Ներբեռնեք `perf-latest` `fkv_bench`-ը fkv պահոցից և գործարկեք նույն ծանրաբեռնվածությունը ֆիքսված մեքենայի վրա:
Համեմատեք թողունակությունը, հետաձգման քվանտիլները և RSS-ի գագաթնակետը C++ ելակետի հետ:

Պարամետրի աղբյուրը համապատասխանում է fkv-ին.

- `PERF_ROWS`
- `PERF_BATCH_SIZE`
- `PERF_WORKLOAD`
- `PERF_BENCH_ROOT`

C++ ելակետը գործարկվում է oracle միջավայրի կողմից `simple_bench` և այնուհետև թողարկվում է նույն սխեմայի համաձայն և հրապարակվում է
`perf-baseline` թողարկման օբյեկտ: Համեմատության արդյունքները հետ են գրվում պահեստի փաստաթղթում, և կայքը ուղղակիորեն ներկայացնում է Markdown-ը:
JSON տվյալների շերտ չի պահպանվում:

Պահպանման հարաբերակցությունը հաշվարկվում է 1M × 128B = 128 ՄԲ անվանական տվյալների հիման վրա; C++-ն այս անգամ չի գործարկում GC/compact,
Այսպիսով, այն պարունակում է պատմության ավելի շատ էջեր: Դա նույն տրամաչափի համարը չէ, ինչ «գոյատևման տվյալների տարածության ուժեղացումը»:
Rust-ի P99.9 պոչի ուշացումը դեռևս ավելի վատ է, քան C++-ը (դրեք 223,3 մս ընդդեմ 86,0 մվ-ի, ստացեք 355,5 մս ընդդեմ
48.2 ms), մեկ բազային գիծը մեծապես տատանվում է, խնդրում ենք մանրամասների համար տե՛ս ներքին կատարողական հաշվետվությունը:

**Նշում**. C++-ի `write-read` նշանակում է, որ գրելու շարանը և ընթերցման շարանը միաժամանակ աշխատում են, իսկ Rust-ը ներկայումս
«Գրիր ավարտիր, նորից բացիր և նորից կարդա», ընթերցման փուլում գրավոր մրցույթ չկա։ Հետևաբար `write-read`-ի բազմապատկիչը չի կարող դիտվել որպես
Մաքուր ընթերցանություն / մաքուր գրավոր եզրակացություն; խիստ համեմատությունը պետք է տեսնել `scripts/perf_local.sh --symmetric`
