# ປະສິດທິພາບ

ດາວໂຫລດ `perf-latest`ຂອງ `fkv_bench`ຈາກ fkv repository ແລະແລ່ນວຽກດຽວກັນຢູ່ໃນເຄື່ອງຄົງທີ່.
ແລະປຽບທຽບ throughput, latency quntiles, ແລະ peak RSS to a C++ baseline.

ແຫຼ່ງພາລາມິເຕີແມ່ນສອດຄ່ອງກັບ fkv:

- `PERF_ROWS`
- `PERF_BATCH_SIZE`
- `PERF_WORKLOAD`
- `PERF_BENCH_ROOT`

ເສັ້ນພື້ນຖານ C ++ ແມ່ນດໍາເນີນການໂດຍສະພາບແວດລ້ອມ oracle `simple_bench` ແລະຈາກນັ້ນໃຫ້ຜົນໄດ້ຮັບຕາມ schema ດຽວກັນແລະຖືກເຜີຍແຜ່ໃນ
`perf-baseline` ປ່ອຍຊັບສິນ. ຜົນໄດ້ຮັບການປຽບທຽບໄດ້ຖືກຂຽນກັບຄືນໄປຫາເອກະສານສາງ, ແລະເວັບໄຊທ໌ໄດ້ສະແດງ Markdown ໂດຍກົງ.
ບໍ່ມີຊັ້ນຂໍ້ມູນ JSON ຖືກຮັກສາໄວ້.

ການວັດແທກເພີ່ມເຕີມ Rust: ສະແກນ `141,166 kv/s`, Fullscan `108,274 kv/s`, ຂຽນ Amplification `2.57x`
(`proc_io_write` 329 MB / 128 MB logical writes), `4.86`ຂຽນລະບົບການໂທຕໍ່ຊຸດ.
ອັດຕາສ່ວນການເກັບຮັກສາແມ່ນຄິດໄລ່ໂດຍອີງໃສ່ 1M × 128B = 128 MB ຂໍ້ມູນນາມ; C ++ ບໍ່ກະຕຸ້ນ GC/compact ໃນເວລານີ້,
ສະນັ້ນມັນມີໜ້າປະຫວັດສາດຫຼາຍຂຶ້ນ. ມັນບໍ່ແມ່ນຕົວເລກ calibre ດຽວກັນກັບ "ການຂະຫຍາຍພື້ນທີ່ຂໍ້ມູນການຢູ່ລອດ".
latency ຫາງ P99.9 ຂອງ Rust ແມ່ນຍັງຮ້າຍແຮງກວ່າ C++ (ໃສ່ 223.3 ms vs 86.0 ms, ໄດ້ 355.5 ms vs.
48.2 ms), ພື້ນຖານດຽວມີການປ່ຽນແປງຢ່າງຫຼວງຫຼາຍ, ກະລຸນາເບິ່ງບົດລາຍງານ perf ພາຍໃນສໍາລັບລາຍລະອຽດ.

**ໝາຍເຫດ**: C++'s `write-read` ໝາຍເຖິງວ່າກະທູ້ຂຽນ ແລະກະທູ້ອ່ານນັ້ນແລ່ນໄປພ້ອມໆກັນ, ແລະ Rust ໃນປັດຈຸບັນ.
"ຂຽນສໍາເລັດ, ເປີດແລະອ່ານອີກເທື່ອຫນຶ່ງ", ບໍ່ມີການແຂ່ງຂັນການຂຽນໃນຂັ້ນຕອນການອ່ານ. ດັ່ງນັ້ນຕົວຄູນຂອງ `write-read`ບໍ່ສາມາດຖືກປະຕິບັດເປັນ
ການອ່ານທີ່ບໍລິສຸດ / ການສະຫລຸບການຂຽນບໍລິສຸດ; ການປຽບທຽບຢ່າງເຂັ້ມງວດຄວນຈະເຫັນ `scripts/perf_local.sh --symmetric`
ສອງຄູ່ຂອງຜົນໄດ້ຮັບແມ່ນ: ການຂຽນເທົ່ານັ້ນແລະອ່ານເທົ່ານັ້ນ. ໝາຍເລກນັກແລ່ນທີ່ແບ່ງປັນອັນດຽວແມ່ນໃຊ້ສຳລັບການຖົດຖອຍເທົ່ານັ້ນ
ແນວໂນ້ມ, ການປ່ອຍອອກມາແມ່ນຕັດສິນໂດຍໃຊ້ຄ່າກາງຂອງ `--runs`.
