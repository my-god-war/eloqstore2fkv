# 2026-11-06: ຕາຕະລາງການປະຕິບັດຫນ້າທໍາອິດ, ການຂະຫຍາຍຕົວຊີ້ວັດແລະຫນ້າ

ການປັບປຸງໃນມື້ນີ້ສຸມໃສ່ການທົບທວນປະສິດທິພາບແລະການເປີດຕົວເວັບໄຊທ໌.

## ການປຽບທຽບການປະຕິບັດຫນ້າທໍາອິດ

- ຫນ້າທໍາອິດຖືກປ່ຽນເປັນບູລິມະສິດການປະຕິບັດ, ແລະຕາຕະລາງການປຽບທຽບ C++/Rust ຈະສະແດງໂດຍກົງໃນຫນ້າຈໍທໍາອິດ.
- ຕົວຊີ້ວັດສາມຊຸດໃຫມ່ໄດ້ຖືກເພີ່ມ: ແບນວິດຢ່າງມີເຫດຜົນ, ການຊັກຊ້າຫາງ P99.9, ແລະການຂະຫຍາຍພື້ນທີ່.
- ເພີ່ມ​ລາຍ​ລະ​ອຽດ​ການ​ແລ່ນ Rust​: ສະ​ແກນ​, Fullscan​, ການ​ຂະ​ຫຍາຍ​ການ​ຂຽນ​, ຈໍາ​ນວນ​ຂອງ​ການ​ໂທ​ລະ​ບົບ​ການ​ຂຽນ​ແລະ synchronization ຂໍ້​ມູນ​ຕໍ່ batch​.
- ໝາຍຢ່າງຈະແຈ້ງ `write-read` ເປັນຂະໜານປະສົມ ແລະ ເຊື່ອມຕໍ່ກັບເອກະສານການປະຕິບັດ.

ພື້ນຖານເຄື່ອງຈັກດຽວກັນໃນປະຈຸບັນ:

| ດັດຊະນີ | C++ | Rust | Rust / C++ |
|---|---:|---:|---:|
| Put | 16,866 kv/s | 21,377 kv/s | 1.27x |
| Get | 5,526 QPS | 7,293 QPS | 1.32x |
| Put P99 | 51.2 ms | 35.1 ms | 0.69x |
| Get P99 | 31.2 ms | 10.0 ms | 0.32x |
| Put P99.9 | 86.0 ms | 223.3 ms | 2.60x |
| Get P99.9 | 48.2 ms | 355.5 ms | 7.37x |
| ສູງສຸດ RSS | 175.6 MiB | 145.5 MiB | 0.83x |
| ການນຳໃຊ້ບ່ອນຈັດເກັບຂໍ້ມູນ | 269.0 MiB | 101.4 MiB | 0.38x |

## ຕົວຊີ້ວັດການປະເມີນຜົນ

ໂດຍອ້າງອີງໃສ່ຜົນຜະລິດທົ່ວໄປຂອງ RocksDB, LevelDB, YCSB, WiredTiger ແລະມາດຕະຖານອື່ນໆ, ຂ້າພະເຈົ້າໄດ້ເພີ່ມ:

- ອ່ານ ແລະຂຽນແບນວິດຢ່າງມີເຫດຜົນ MiB/s;
- P99.9 ຫາງຊັກຊ້າ;
- ການຂະຫຍາຍພື້ນທີ່, ການຂຽນຂະຫຍາຍ;
- ຈໍານວນການຂຽນລະບົບການໂທແລະການ synchronization ຂໍ້ມູນໃນແຕ່ລະ batch;
- ສະແກນ / Fullscan ຜ່ານ;
- CPU, ຄວາມຜິດຂອງຫນ້າ, ສະຫຼັບສະພາບການ, ແລະຂະບວນການ IO ສືບຕໍ່ຖືກເກັບກໍາໂດຍ sidecar ຊັບພະຍາກອນ.

ກິນເບັ້ຍບໍານານໃນເວລາດຽວກັນ`gxhash_4096B_gib_s`. ມັນເປັນ 4 KiB single block hash microbenchmark ທີ່ບໍ່ໄດ້ຢູ່ໃນເສັ້ນທາງເຄື່ອງຈັກ KV ແລະບໍ່ມີຄູ່ C++.

## ການແກ້ໄຂແລະວິສະວະກໍາທີ່ຖືກຕ້ອງ

- ແກ້ໄຂພື້ນທີ່ກະແຈຂອງ `--rng cpp` ອ່ານ/ສະແກນ: ການກວດຫາການອ່ານຈະບໍ່ຖືກຄູນດ້ວຍ `key_interval` ເພື່ອຫຼີກເວັ້ນການອ່ານ 75% ຕົກຢູ່ໃນກະແຈທີ່ບໍ່ໄດ້ຂຽນ.
- ແກ້ໄຂການພະຍາຍາມສະແຕນບາຍທີ່ເກີດຈາກ macOS `openrsync`ການຕັດສິນຜິດຂອງ manifests ທີ່ມີເນື້ອໃນດຽວກັນ.
- ແກ້ໄຂບັນຫາປະຕູຮາດແວທີ່ QEMU virtual disks ຖືກຕັດສິນຜິດເປັນ SSDs ທ້ອງຖິ່ນ.
