# パフォーマンス

fkv リポジトリから `perf-latest` または `fkv_bench` をダウンロードし、固定マシンで同じワークロードを実行します。
また、スループット、レイテンシ分位数、およびピーク RSS を C++ ベースラインと比較します。

パラメータ ソースは fkv と一致しています。

- `PERF_ROWS`
- `PERF_BATCH_SIZE`
- `PERF_WORKLOAD`
- `PERF_BENCH_ROOT`

C++ ベースラインは Oracle 環境`simple_bench`によって実行され、同じスキーマに従って出力され、
`perf-baseline` アセットをリリースします。比較結果はウェアハウス ドキュメントに書き戻され、サイトは Markdown を直接レンダリングします。
JSON データ層は維持されません。

## 現在の結果

2026-11-06T04:25Z のスキーマ 2 ベースライン、`github-ubuntu-latest-x86_64`、4 KiB ページ、
`data_append_mode=false`、`direct_io=true`。固定ワークロード:
`rows/max_key=1000000`、`batch_size=100`、`write_batchs=10000`、
`read_per_part=4`、`partitions=1`、`kv_size=128`、`rng=cpp`
(`key_interval=4` / `del_ratio=4`)、`test_secs=30`。

| プロジェクト | C++ EloqStore | Rust fkv | Rust / C++ |
|---|---:|---:|---:|
| プットスループット | 16,866 kv/s | 21,377 kv/s | 1.27x |
| スループットを取得する | 5,526 QPS | 7,293 QPS | 1.32x |
| 論理帯域幅を置く | 2.06 MiB/s | 2.61 MiB/s | 1.27x |
| 論理帯域幅を取得する | 0.67 MiB/s | 0.89 MiB/s | 1.32x |
| Put P99 | 51.2 ms | 35.1 ms | 0.69x |
| Get P99 | 31.2 ms | 10.0 ms | 0.32x |
| Put P99.9 | 86.0 ms | 223.3 ms | 2.60x |
| Get P99.9 | 48.2 ms | 355.5 ms | 7.37x |
| ピーク RSS | 175.6 MiB | 145.5 MiB | 0.83x |
| ストレージの使用量 | 269.0 MiB | 101.4 MiB | 0.38x |
| ストレージ/公称データ | 2.20x | 0.83x | 0.38x |

100 万エントリ (10,000 バッチ) の書き込みは、
`io_write_at_num=48,625`、`io_data_sync_num=10,000`、つまりデータはバッチごとに 1 回同期されます。
Rust の追加メトリクス: スキャン `141,166 kv/s`、フルスキャン `108,274 kv/s`、書き込み増幅 `2.57x`
(`proc_io_write` 329 MB / 128 MB 論理書き込み)、`4.86` バッチごとにシステム コールを書き込みます。
ストレージ率は、1M × 128B = 128 MB の公称データに基づいて計算されます。今回は C++ が GC/compact をトリガーしません。
したがって、より多くの歴史のページが含まれています。 「サバイバル データ スペース アンプリフィケーション」と同じ口径番号ではありません。
Rust の P99.9 テール レイテンシーは、C++ よりもさらに悪いです (出力 223.3 ミリ秒対 86.0 ミリ秒、取得 355.5 ミリ秒対
48.2 ミリ秒）、単一のベースラインは大きく変動します。詳細については、内部パフォーマンス レポートを参照してください。

**注意**: C++ の`write-read`とは、書き込みスレッドと読み取りスレッドが同時に実行されることを意味し、現在 Rust は
「書き終えて、もう一度開いて、また読む」、読書の段階では書き競争はありません。したがって、 `write-read` の乗数は次のように扱うことができません。
純粋な読書と純粋な執筆の結論。厳密な比較は `scripts/perf_local.sh --symmetric` を参照してください。
書き込み専用と読み取り専用の 2 つの結果ペアが出力されます。単一の共有ランナー番号は回帰にのみ使用されます
トレンド、リリースは`--runs`の中央値を使用して判断されます。
